# Domain docs

## Before exploring

This repo uses a single-context layout:

- Read `GLOSSARY.md` at the repo root.
- Read relevant decisions in `docs/adr/`.

If either is absent, proceed silently. The domain-modeling skill creates
them when terminology or decisions are resolved; do not scaffold them
merely because they are missing.

## Vocabulary

Use glossary terms in issue titles, proposals, hypotheses, and test names.
Reconsider invented synonyms. Note real vocabulary gaps for domain-modeling.

## Decisions

If a proposal contradicts an existing ADR, identify the ADR and explain
why the decision should be reconsidered.
